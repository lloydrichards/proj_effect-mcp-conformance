# Tasks recheck with conformance alpha.12

The 6 October recheck used conformance `0.2.0-alpha.12` and the existing locally packed Effect `4.0.0-rc.118` Tasks implementation. Seven scenarios pass, one fails, and one is skipped. The task-response schema failures recorded on 1 October are resolved.

- Passing: lifecycle, capability negotiation, wire fields, request-state removal, MRTR input, request headers, and required-task error.
- Failing: dispatch/envelope, with 8 of 9 checks passing. The runner still sends `{ "unknown-key": { "ignored": true } }`, which fails parameter validation. The bundled source confirms the unchanged invalid stimulus.
- Skipped: status notifications, pending the upstream subscriptions/listen harness rewrite.

See [the original investigation](task-failures-investigation.md) for schema validation and the valid-input control. No Effect production change was indicated by this recheck. Local logs remain in `.cache/tasks-alpha12/`.

The Tasks PR must remain a draft until the Tasks implementation lands upstream and a published Effect package exports its APIs. CI installs published packages and does not build the sibling checkout. Updating the conformance runner alone does not remove that blocker.
